# 2026-10-15 - From an empty repository to the plug-in, then Apple's HIG

The user asked for a JSFX that, given two samples, swaps their attacks: sample
1 keeps its own sustain but takes sample 2's transient. They attached REAPER's
JSFX language reference and API reference, linked Apple's Human Interface
Guidelines, and pointed to Miderator for the house colour scheme. They later
sent the full set of Apple's Foundations pages and asked for the plug-in to
be checked against them.

Two commits on `claude/loving-carson-xcyc30`, with no pull request yet:
`c4df23c` (the plug-in) and `07776b7` (the HIG changes). Decisions
0001-0011.

## The route

- **The house colours.** Miderator (public, read-only here) has them in
  `Source/App/Theme.h`, and its 0015 and 0031 give the rules: blue-shifted
  greys, dark text on every button, one yellow, red only for warnings. Its
  values were copied as they are (0009).
- **The JSFX API without its documentation.** reaper.fm is blocked by the
  network policy, and the attached API page covers ReaScript, not JSFX file
  reading. The calls were checked against real code instead:
  - file reading and dropped files from Saike's (JoepVanlier/JSFX) and
    ReaTeam's collections;
  - the cursor ids from Saike;
  - how `gfx_showmenu` numbers its items: separators aren't counted, greyed
    items are.

  `export_buffer_to_project` appears in neither collection. It was written
  from memory and is flagged as unverified (0006).
- **A way to run it.** WDL's `loose_eel` was built here with REAPER's loop
  limit. `tests/run_tests.py` splits the JSFX into its sections, swaps
  REAPER's calls for stand-ins, and runs it at the real memory size and a
  small one (0008). The first run compiled everything and failed three checks
  out of 230. None was a fault in the plug-in (below).
- **The sound** (0002-0005):
  - hits found by a threshold below each sample's peak and lined up there;
  - the attack copied exactly, 5 ms before the hit onwards;
  - a crossfade whose curves hold the level for any degree of likeness,
    after aligning phase and polarity;
  - the body copied whole;
  - the attack levelled to the peak of the attack it replaces.

  The checks that prove it: a sound given its own attack comes back
  unchanged; an upside-down copy comes back the right way up; two unrelated
  noises keep their level.
- **Pictures of the window.** `tests/render_preview.py` prints every drawing
  call instead of making it, and PIL draws them. The first pictures showed:
  - dots at the corners of dimmed buttons, where the rounded rectangle's
    see-through pieces overlapped. Fixed by mixing the colour solid
    (`mix()`);
  - file details that might be cut short. Fixed by widening the label column
    and shortening the line;
  - the ruler showing "1000 ms". It now shows "1 s".
- **Apple's Foundations.** All 19 files in the user's zip were the same
  17 KB page, saved before its text had loaded. Each linked to a Markdown
  version on developer.apple.com, so all 19 were fetched from there. The
  plug-in was checked against each, with contrast measured for every pair of
  text and background colours. What changed (0010):
  - Undo, and messages that stay until dismissed;
  - full keyboard control;
  - Play that becomes Stop;
  - contrast of at least 7:1 for text;
  - interface size;
  - the system font;
  - controls moved to the top;
  - yellow given one meaning;
  - "(unused)" written on the waveforms;
  - errors shown in their own row;
  - *Hit threshold* instead of *Onset threshold*.

  The checks went from 230 to 677. The review is in
  `docs/apple-hig-review.md`.
- **The pages themselves.** The user asked for them in the repository. It is
  public and the pages are Apple's copyrighted text, so the user was asked
  first. They chose a download instead: a zip of 19 Markdown files (0011).

## What looked wrong and wasn't

- **"250 ms attack, other way" failed the smoothness check.** That result is
  the 808's loud attack crossfaded into the punchy kick's body. By 250 ms
  that body has decayed to a twentieth, and the crossfade was 0.5 ms long,
  so the steep drop is real. The check for that case now tests that the
  result is exact, not that it is smooth.
- **"Voices are reused in turn" expected `next_v == 0`.** The voices had
  already been used earlier in the run, so the counter didn't start at 0.
  The test was wrong.
- **"A double-click puts the slider back" failed.** The pointer was still
  past the slider's end from the drag before. The test was wrong.
- **File details showed "1…" in the previews.** The preview estimates text
  width from bytes, and "·" takes two. REAPER measures properly. The line
  was shortened anyway.
- **The 200% preview looked exactly like the normal one.** It was drawn in a
  window twice as big, so it should look the same.
- **An error line drawn at the top of its row.** The preview script didn't
  handle bottom-aligned text. It does now.

## Mistakes

- `tests/__pycache__` went into the first commit. It was removed in the
  second, and `.gitignore` now keeps it out.
- The first window put yellow on the splice line while it was dragged,
  timed messages out after 4 seconds, and had all its controls at the bottom.
  All three go against Apple's guidelines, and the review changed them.
- The session's worker restarted mid-way through the first test run. Nothing
  was lost, because the files were already on disk, but the work hadn't been
  committed yet.

## Not done yet

- **Nothing has been tried in REAPER.** Unverified (CLAUDE.md, "Where it
  stands"):
  - where `export_buffer_to_project(…, -1, 0)` puts the item;
  - whether `file_riff` reads files other than WAV;
  - whether `gfx_getfont(#str)` works and `.AppleSystemUIFont` gives San
    Francisco;
  - whether REAPER passes Tab and the arrow keys to the window;
  - whether `file_open` works from `@block`.
- No way to load a sample without dragging, because JSFX has no file dialog.
- Samples are cut at 16.6 s (at 48 kHz).
- Voices ignore note-offs, and a reused voice cuts off without a fade.
- At 200% in a small window, the rows run off the bottom.
- The hit is found by one threshold. A sample with two hits, or noise before
  its hit, needs the threshold adjusting by hand. There's no way to move a
  hit marker by hand.
- No pull request has been opened.
